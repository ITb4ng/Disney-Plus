# v0.3.0 Release Notes

날짜: `2026-03-16`

## 요약
- 라우트별 스크롤 복원 정책을 `/`, `/main`, `/detail` 기준으로 재정의했다.
- 브라우저 새로고침과 뒤로 가기 복원을 분리해 복잡한 상태 분기를 줄였다.
- `/main`, `/detail`은 새로고침 전용 오버레이를 사용하고, `/`는 섹션 최소 복원 방식으로 정리했다.
- 관련 테스트 파일 이름과 디버그 URL 문서를 현재 목적에 맞게 정리했다.

## 변경 사항

### 1. `/main` 스크롤 정책 정리
- `/main` 하드 리로드는 복원보다 새로고침 전용 오버레이 UX를 우선한다.
- 최상단 새로고침은 top 유지, 스크롤 후 새로고침은 오버레이 뒤에서 컨텐츠를 렌더한 뒤 top 기준으로 시작한다.
- detail 등 다른 라우트에서 `/main`으로 돌아오는 경우에는 기존 스크롤 복원을 유지한다.

### 2. `/` Landing 최소 복원 도입
- `/`는 px 단위 정밀 복원이 아니라 섹션 단위 최소 복원으로 바꿨다.
- hero는 복원 대상에서 사실상 제외하고 top 유지로 처리한다.
- top10, pricing, faq, footer는 절반 이상 기준으로 해당 섹션 최상단이 nav 아래에 오도록 맞춘다.

### 3. `/detail` 새로고침 정책 정리
- `/detail`의 기본 동작은 top 0이다.
- 브라우저 새로고침에서만 trailer 또는 row가 직전 화면에서 절반 이상 보였을 때 해당 래퍼 최상단을 nav 아래에 맞춘다.
- detail 내부 row 포스터 클릭 시 다음 detail로 이동하면서 상단으로 올리는 동작은 유지한다.
- footer 선노출 플래시는 오버레이로 가린다.

### 4. 스크롤 정책 코드 구조 정리
- 라우트별 하드 로드 정책을 `src/components/scrollRestoreRoutePolicy.js`로 분리했다.
- `ScrollManager`는 저장, 복원 시도, 완료 시점 제어 역할만 남기고 분기 책임을 줄였다.
- 불필요한 디버그 로그를 정리해 콘솔 노이즈를 줄였다.

### 5. 테스트와 문서 정리
- Playwright 스펙 파일명을 목적에 맞게 변경했다.
  - `tests/main-scroll-restore.spec.js` -> `tests/main-route-scroll-policy.spec.js`
  - `tests/scroll-restoration.spec.js` -> `tests/cross-route-scroll-policy.spec.js`
- `tests/debug-url-matrix.md`를 현재 스크롤 정책과 테스트 파일명 기준으로 업데이트했다.

- Playwright 재실행 기준으로 일부 기대값은 현재 수동 검증 결과와 차이가 있어 후속 보정이 필요하다.
- 현재 확인된 항목
  - `/main` 리로드 후 top reset 기대값 1건
  - `/detail` row 리로드 정렬 기대값 1건
- 실사용 체감과 수동 검증은 정상으로 판단되어 이번 버전에서는 보류한다.
