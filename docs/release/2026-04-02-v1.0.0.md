# v1.0.0 Release Notes

날짜: `2026-04-02`

## 배포 결정
"0.3.0에대한 수정과 이슈를 보완하고 개선해서 1.0.0 릴리즈 배포를 결정함."

이번 `v1.0.0`은 `v0.3.0` 이후 확인된 보완 필요 사항을 정리하고, 실제 사용자 경험과 운영 관점에서 필요한 안정화 작업을 마친 뒤 진행하는 릴리즈다.  
단순 기능 추가보다 구조 정리, 반응형 UX 개선, 테스트 보강, 한글/문구 정리, 미사용 코드 정리까지 포함한 안정화 배포 성격이 강하다.  
이번 `v1.0.0`은 현재 코드베이스를 프로덕션 메인 브랜치의 기준선으로 확정하는 릴리즈이며, 그동안 이어진 주요 개선 작업에 종지부를 찍는 버전이다.

## 목적
- `v0.3.0` 이후 남아 있던 수정 포인트와 보류 이슈를 재검토하고, 실제 배포 가능한 수준으로 정리한다.
- 피드백 페이지와 등록 폼을 사용자 관점에서 더 직관적이고 일관된 UX로 개선한다.
- 반응형 품질과 테스트 커버리지를 보강해 모바일, 태블릿, 데스크탑 대응력을 높인다.
- 상태 UI와 fallback 흐름을 정리해 예외 상황에서도 레이아웃과 사용자 경험을 안정적으로 유지한다.
- `1.0.0` 이후 운영 과정에서 발생할 수 있는 이슈는 `hotfix` 브랜치 전략으로 빠르게 대응할 수 있는 기준을 마련한다.

## v0.3.0과 v1.0.0의 차이

### 1. 릴리즈 성격
- `v0.3.0`
  - 스크롤 복원 정책과 라우트 단위 동작 정리에 초점이 있었다.
- `v1.0.0`
  - 사용자 체감 UX, 반응형 안정화, 상태 UI, 테스트 자동화, 문서화까지 범위를 넓힌 릴리즈다.

### 2. 사용자 경험 범위
- `v0.3.0`은 스크롤 정책 중심이었다.
- `v1.0.0`은 피드백 흐름, 모바일 UI, 안내 박스, 계정 가이드, 배너/모달/상세 fallback까지 실제 사용 흐름 전반을 정리했다.

### 3. 품질 보증 범위
- `v0.3.0`은 스크롤 관련 테스트와 수동 검증 비중이 컸다.
- `v1.0.0`은 반응형 체크리스트, Playwright 기능 테스트, 비주얼 테스트, 앱 스모크 테스트, ESLint 정리까지 포함한다.

### 4. 코드베이스 정리 수준
- `v0.3.0`은 정책 로직 정리에 집중했다.
- `v1.0.0`은 페이지/컴포넌트 구조 분리, 한글 문구 정상화, 미사용 스타일 제거, 상태 UI/fallback 정리까지 포함한 품질 개선 릴리즈다.

## 주요 포함 내용

### 1. 피드백 페이지 / 등록 폼 개선
- 피드백 페이지와 등록 폼을 헤더, 툴바, 카드, 콘텐츠, helper, 스타일 단위로 분리했다.
- 등록, 삭제, 오류, 검증 메시지를 공용 안내 박스 흐름으로 통일했다.
- 계정 상태 안내와 등록 가능 여부 문구를 더 직관적으로 정리했다.
- 모바일 기준 툴바, 메타 정보, 뒤로가기 버튼, 가이드 카드, 본문 길이, 날짜 표기 등을 실사용 중심으로 다듬었다.

### 2. State UI / Fallback 안정화
- `loading`, `error`, `empty` 상태를 각 페이지와 컴포넌트 단위에서 분리해 테스트 가능하도록 정리했다.
- `no-image`, `image-error`, `cdn-fail` 디버그 상태를 공통 매트릭스에 반영했다.
- `Row`, `MovieModal`, `Detail hero`에 fallback UI를 일관된 기준으로 적용했다.
- `Landing Hero`, `Top10`, `Main Banner`, `SearchPage`에도 동일한 fallback 디버그 흐름을 연결했다.
- 잘못된 접근과 예외 상황에서도 레이아웃이 유지되도록 안전한 fallback 구조를 적용했다.
- Detail 하단 `trailer`, `related row`는 이미지 fallback 상태와 분리해 정상 노출이 유지되도록 정리했다.
- `main -> modal -> detail` 이동 시 `location.state` 기반 debug 상태 전달이 이어지도록 맞췄다.

### 3. 반응형 및 테스트 체계 보강
- 피드백 페이지에 대한 수동 반응형 체크리스트를 문서화했다.
- Playwright로 피드백 반응형 기능 테스트와 비주얼 스냅샷 테스트를 추가했다.
- `package.json`에 피드백 전용 테스트 스크립트를 추가해 실행 편의성을 높였다.
- `App.test.js`를 현재 앱 구조에 맞는 스모크 테스트로 교체했다.
- `Row.test.jsx`의 Testing Library ESLint 오류를 정리해 테스트 품질 기준을 맞췄다.

### 4. 한글 / 문구 / 코드 정리
- FAQ, Footer, Row 관련 한글 문구와 주석을 정리해 가독성과 유지보수성을 높였다.
- 유니코드 이스케이프와 깨진 한글 흔적을 점검하고 정상화했다.
- 실사용되지 않는 `badges.css`와 관련 import를 제거했다.

### 5. 배너 관련 기반 정리
- 배너 후보 seed, 가중치 랜덤 선택, seed 유효성 검증, fallback 흐름을 분리해 배너 관리 구조를 정리했다.
- 배너 로직을 데이터 구성, 선택 로직, 검증 레이어로 나누어 이후 운영과 수정이 쉬운 형태로 만들었다.

## 기대 효과
- 피드백 기능 사용 흐름이 더 명확해지고, 모바일에서의 가독성과 조작성이 좋아진다.
- 상태 UI와 이미지 fallback 흐름이 통일돼 예외 상황에서도 사용자가 갑작스럽게 끊기는 느낌을 덜 받는다.
- 반응형 검증과 자동화 테스트가 갖춰져 이후 회귀 위험을 줄일 수 있다.
- 배포 전 품질 이슈를 줄여 `1.0.0` 기준선으로 삼기 쉬운 코드 상태를 확보한다.

## 검증 기준
- `npm run build` 통과
- `src/App.test.js` 통과
- `eslint src --ext .js,.jsx` 에러 없음
- 피드백 반응형 Playwright 테스트 통과
- 피드백 비주얼 Playwright 테스트 통과
- 주요 JSX/CSS 파일 한글 깨짐 여부 점검 완료

## 릴리즈 메모
- `v0.3.0`에서 기록했던 보류 이슈 중 일부는 정책 재정의 또는 테스트 재검토를 통해 범위를 재정리했다.
- 스크롤 복원 정책 관련 추가 검토 포인트는 별도 diff review 문서에서 추적한다.
- 이번 릴리즈는 기능 확장보다 안정화와 품질 향상에 더 큰 의미가 있다.

## 후속 조치 및 이후 대응
- 배포 이후 이슈 대응은 `hotfix` 브랜치를 생성하고 그 브랜치에서 수정 후 배포한다.
- 사용자 영향도가 큰 오류는 `hotfix` 우선순위로 분류해 빠르게 대응한다.
- 릴리즈 직후에는 피드백 페이지, 배너 노출, 주요 라우트 이동, 모바일 반응형 화면을 우선 모니터링한다.
- 추가 개선 과제는 운영 이슈와 분리해 다음 마이너 버전 작업으로 관리한다.
