# Feedback Responsive Manual Checklist

## 목적
- 피드백 관련 UI를 수동으로 반응형 점검한다.
- 페이지 단위와 컴포넌트 단위로 확인한다.
- 수동 점검 결과 이상이 없으면 Playwright 반응형 테스트 시나리오로 전환한다.

## 테스트 뷰포트
- [ ] `360 x 800`
- [ ] `390 x 844`
- [ ] `430 x 932`
- [ ] `768 x 1024`
- [ ] `1024 x 768`

## 공통 점검 기준
- [ ] 좌우 잘림 없이 안전 영역 안에서 보인다.
- [ ] 텍스트 줄바꿈이 어색하지 않다.
- [ ] 버튼과 입력창 터치 영역이 충분하다.
- [ ] 고정 영역이 콘텐츠를 과하게 가리지 않는다.
- [ ] 스크롤 시 레이아웃이 흔들리지 않는다.
- [ ] 로딩, 성공, 오류 상태에서 레이아웃이 무너지지 않는다.

## 페이지 단위 체크

### 1. Feedback Page
- [ ] 상단 제목, 안내 문구, 칩이 첫 화면에서 자연스럽게 읽힌다.
- [ ] `피드백 건수 / 접속 계정` 칩이 모바일에서 반반 강제 분할되지 않는다.
- [ ] 안내 카드 문구가 줄바꿈 포함 상태에서 과하게 길어 보이지 않는다.
- [ ] 툴바에서 모바일은 `정렬` 라벨 없이도 의미 전달이 된다.
- [ ] 셀렉트, 새로고침, 등록 버튼 간 간격과 위계가 명확하다.
- [ ] 카드 제목 2줄 제한이 자연스럽다.
- [ ] 카드 본문 3줄 프리뷰가 자연스럽고, 메타 정보와 충돌하지 않는다.
- [ ] 날짜 포맷이 모바일에서 길지 않고 한눈에 읽힌다.
- [ ] 하단 `이전 화면` 버튼이 목록을 과하게 덮지 않는다.
- [ ] 목록이 1개일 때, 여러 개일 때, 0개일 때 모두 안정적이다.

### 2. Feedback Form Create
- [ ] 브레드크럼과 `목록으로` 버튼이 모바일에서 겹치지 않는다.
- [ ] 체험 계정 안내 배너가 모바일에서 과하게 길지 않다.
- [ ] 제목 input과 내용 textarea의 16px 폰트가 유지된다.
- [ ] 모바일 Safari/Chrome 기준 자동 확대가 발생하지 않는다.
- [ ] 버튼 disabled, pending 상태가 시각적으로 구분된다.
- [ ] 안내 박스가 표시될 때 폼 입력과 겹침이 어색하지 않다.

### 3. Feedback Form Edit
- [ ] 수정 모드 진입 시 기존 데이터 로딩 레이아웃이 안정적이다.
- [ ] 수정 권한이 없을 때 안내 박스와 이동 흐름이 자연스럽다.
- [ ] 수정 완료 후 목록 복귀와 안내 문구가 자연스럽다.

## 컴포넌트 단위 체크

### 1. FeedbackPageHeader
- [ ] `PageLead` 줄바꿈이 의도대로 보인다.
- [ ] 디버그 배지가 있을 때도 헤더 줄배치가 무너지지 않는다.
- [ ] 계정 칩 라벨과 값의 대비가 충분하다.

### 2. FeedbackToolbar
- [ ] 데스크탑은 세그먼트 정렬 버튼이 자연스럽다.
- [ ] 모바일은 셀렉트만으로 정렬 의도가 충분히 전달된다.
- [ ] `등록`은 primary, `새로고침`은 secondary로 명확하다.

### 3. FeedbackCardItem
- [ ] 제목, 뱃지, 삭제 버튼이 한 줄에서 안정적으로 배치된다.
- [ ] `체험계정` 뱃지가 너무 크거나 튀지 않는다.
- [ ] 삭제 버튼이 다른 메타 정보보다 명확하게 구분된다.
- [ ] 카드 클릭 가능 상태와 비활성 상태가 혼동되지 않는다.

### 4. FeedbackNoticeOverlay
- [ ] 성공 안내 박스가 모바일 중앙에서 잘 보인다.
- [ ] 삭제 확인 박스 버튼 `확인 / 취소`가 충분히 눌리기 쉽다.
- [ ] 배경 블러가 과하게 하얗지 않다.
- [ ] 자동 닫힘 시간이 너무 짧거나 길지 않다.

### 5. Feedback Skeleton
- [ ] shimmer 속도가 과하지 않다.
- [ ] 스켈레톤 카드 높이가 실제 카드와 크게 다르지 않다.
- [ ] 스켈레톤 상태에서 스크롤 체감이 거슬리지 않는다.

### 6. Mobile Back Button
- [ ] `이전 화면` 버튼이 세컨더리 액션처럼 보인다.
- [ ] 버튼 폭이 텍스트 길이에 맞게 자연스럽다.
- [ ] safe-area와 겹침 없이 하단에 안정적으로 붙는다.
- [ ] 리스트 마지막 카드 내용을 과하게 가리지 않는다.

## 상태별 점검
- [ ] `loading`
- [ ] `empty`
- [ ] `error`
- [ ] `guest`
- [ ] `refreshing`
- [ ] `create-toast`
- [ ] `delete-toast`

## 수동 점검 후 기록
- [ ] 이상 없음
- [ ] 수정 필요 항목 기록 완료
- [ ] 스크린샷 확보 완료

## Playwright 전환 조건
- [ ] 주요 뷰포트 5개에서 레이아웃 이슈 없음
- [ ] 버튼 겹침, 텍스트 잘림, fixed 영역 충돌 없음
- [ ] 수동 확인 기준 핵심 시나리오 확정 완료

## Playwright 후보 시나리오
- [ ] 모바일 피드백 페이지 진입 시 헤더, 칩, 툴바가 정상 노출된다.
- [ ] 모바일에서 카드 제목, 본문 프리뷰, 메타 정보가 정상 노출된다.
- [ ] 모바일에서 `이전 화면` 버튼이 하단 safe-area 안에 정상 노출된다.
- [ ] `?debug=loading`
- [ ] `?debug=empty`
- [ ] `?debug=error`
- [ ] `?debug=guest`
- [ ] `?debug=refreshing`
- [ ] `?debug=create-toast`
- [ ] `?debug=delete-toast`
