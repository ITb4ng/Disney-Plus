## 1. 오늘 작업의 핵심은 "기능 추가"보다 구조 정리와 UX 안정화였다

오늘 작업은 새 기능을 더 붙이는 방향보다, 이미 쌓여 있던 UI와 구조를 이전 `v0.3.0` 기준에서 다시 정리하는 쪽에 가까웠다.

중심 축은 크게 네 가지였다.

- 페이지 구조 리팩토링
- 메인과 랜딩의 모바일 인터랙션 정리
- 모달, 스크롤, 라우팅 흐름 보정
- 깨진 문자열과 인코딩 정리

처음에는 각각 독립된 이슈처럼 보였지만, 실제로는 같은 문제로 연결되어 있었다.  
공용 컴포넌트와 페이지 전용 컴포넌트의 경계가 흐려져 있었고, 모바일과 데스크톱 인터랙션 기준도 섞여 있었고, 그 위에 인코딩이 깨진 문자열과 오래된 구조가 계속 겹치고 있었다.

결국 오늘은 "눈에 보이는 버그를 하나씩 고친다"보다는 "구조를 다시 나눠서 이후 수정 비용을 낮춘다" 쪽으로 방향을 잡았다.

## 2. 페이지 구조를 역할 기준으로 다시 나눴다

오늘 구조 정리에서 가장 먼저 잡은 것은 `pages`와 `components`의 경계였다.

이전에는 `src/components` 안에 실제로는 `MainPage`에서만 쓰는 UI가 꽤 많이 들어가 있었다.  
이 상태에서는 공용 컴포넌트처럼 보이지만 실제 재사용 범위는 한 페이지에만 묶여 있어서, 파일을 찾을 때도 혼동이 있었고 구조를 설명하기도 어려웠다.

그래서 다음 기준으로 정리했다.

- 여러 페이지에서 재사용되는 것만 `src/components`
- 한 페이지에서만 쓰는 UI는 `src/pages/<Page>/components`
- 라우트로 직접 진입하는 화면은 `src/pages`

이 기준으로 다음 구조를 정리했다.

- `DemoPage` -> `FeedbackPage`
- `LoginPage` -> `LandingPage`
- `NotFoundPage` -> `pages/NotFound`
- `MainPage` 전용 UI를 `src/pages/MainPage/components`로 이동
- `DetailPage` 전용 뷰와 훅도 페이지 하위 구조로 분리

파일명도 같이 맞췄다.

- `FAQitem.jsx` -> `FAQItem.jsx`
- `FAQdata.js` -> `FAQData.js`
- `Bundle.js` -> `BundlePromo.jsx`

오늘 구조 정리는 "지금 예쁘게 보이게 만드는 것"보다 "다음 수정 때 어디를 건드려야 하는지 바로 보이게 만드는 것"에 더 가까웠다.
유지보수는 늘 중요하고 코드를 용이하게 작성을 하자.

## 3. 메인 페이지는 모바일에서 hover를 걷어내고 active, click 중심으로 다시 정리했다

오늘 메인 페이지에서 가장 크게 본 문제는 모바일 터치 환경에서 hover가 과도하게 개입한다는 점이었다.

데스크톱 기준으로 만든 hover 전환이 모바일에서도 그대로 반응하면서,

- 스크롤 중에 카드가 들쑥날쑥 움직이고
- 패럴랙스나 spotlight 효과가 터치 환경에서 과하게 남고
- 오버레이가 의도치 않게 열리고 닫히는 흐름이 생겼다.

그래서 기준을 분리했다.

### 3-1. `Category`
- 모바일에서는 hover 대신 click, active 기준으로만 동작
- 바깥 영역 탭 시 active 해제
- active 카드만 영상 재생
- 나머지 카드는 pause/reset 처리

### 3-2. `DemoAction`
- 모바일에서는 hover와 spotlight 제거
- 데스크톱에서만 spotlight와 hover 유지

### 3-3. `Banner`
- 모바일에서는 스크롤 시 비네팅만 유지
- Y 패럴랙스는 제거
- 데스크톱에서는 기존 인터랙션 유지

### 3-4. `Row`
- 모바일에서는 hover 제거
- 오버레이를 기본 노출로 바꿔 영화 정보가 항상 보이도록 정리
- 데스크톱은 hover, focus 기준 유지

이렇게 나누고 나니 모바일에서는 터치 환경 기준 UX가 더 안정적으로 보이고, 데스크톱에서는 기존 인터랙션 감각을 유지할 수 있었다.

## 4. `MovieModal`, 스크롤, 404, 피드백 흐름을 한 번에 정리했다

오늘 수정 중 가장 엮여 있던 영역은 모달과 스크롤 흐름이었다.

### 4-1. `MovieModal`
처음에는 단순히 z-index만 높이면 될 것 같았지만, 실제로는 stacking context와 scroll container가 문제였다.

- 모달을 `createPortal(..., document.body)`로 이동
- `fixed`, `z-index`, scroll lock 기준 재정리
- iPhone safe area 반영
- 모바일 내부 스크롤과 배경 스크롤 문제 보정

이 과정에서 `/` 모바일에서 `PricingSection` 타이틀이 모달 뒤로 비치던 문제도 함께 정리됐다.

### 4-2. 404
- 어떤 화면에서 404로 들어가도 항상 최상단에서 시작
- 뒤로가기는 이전 페이지 스크롤 복원 유지

### 4-3. 피드백 흐름
- 메인 -> 피드백 -> 등록 -> 목록 -> 뒤로가기 시 메인 스크롤 위치 유지
- `FeedbackForm`은 인라인 스타일을 걷어내고 `styled-components`로 정리

결국 이 부분은 화면 하나만 보는 수정이 아니라, 라우팅과 레이아웃 전체를 같이 봐야 안정화가 가능했다.

## 5. 랜딩 페이지는 타이포, spacing, footer를 중심으로 다시 다듬었다

랜딩(`/`)은 눈에 띄는 기능 버그보다 "섹션마다 기준이 조금씩 다른 상태"가 더 크게 보였다.

그래서 오늘은 `Hero`를 제외한 주요 섹션을 다음 기준으로 다시 정리했다.

- `Top10`
- `Pricing`
- `FAQ`
- `Footer`

### 5-1. 타이틀 스케일 정리
`Pricing` 타이틀에서 이미 잘 동작하던 `clamp()` 기준을 `Top10`, `FAQ`에도 맞췄다.

결과적으로 섹션 타이틀은 화면이 줄어들수록 자연스럽게 축소되고, 데스크톱에서는 현재 폭을 크게 흔들지 않는 방향으로 정리됐다.

### 5-2. `FAQ`, `Pricing` CSS 재정리
처음에는 토큰을 많이 두는 방향으로 갔지만, 실제로는 한 번만 쓰는 값까지 변수화되면서 읽기 비용이 커졌다.

그래서 오늘 후반에는 다시 기준을 바꿨다.

- 공통으로 정말 많이 쓰는 값만 토큰화
- 나머지는 컴포넌트 안 직접값으로 유지
- `desktop / laptop / tablet / mobile` 순서로 미디어쿼리 정리

### 5-3. `Footer`
`Footer`는 모바일에서 손본 부분이 많았다.

- 모바일 아코디언 spacing 정리
- 마지막 컬렉션 영역 border 처리
- legal/sns 간격 보정
- 열림 애니메이션 정리
- 초소형 모바일부터 큰 모바일까지 로고 선명도와 크기 보정

랜딩은 기능을 추가한 날은 아니었지만, 화면 완성도 관점에서는 오늘 가장 체감이 큰 수정이 이 영역이었다.

## 6. 깨진 문자열과 주석을 계속 복구하면서 코드베이스를 정리했다

오늘 작업 내내 같이 따라다닌 문제는 인코딩이었다.

특히 다음 영역에서 깨진 문자열이 반복적으로 보였다.

- 랜딩 페이지 문구
- 메인 페이지 문구
- 피드백 페이지 문구
- `README`
- 일부 CSS 주석

겉으로는 문장 몇 개만 깨진 것처럼 보여도, 실제로는 빌드나 JSX 문법까지 흔드는 케이스도 있었다.  
대표적으로 `Row.jsx`는 깨진 문자열 때문에 빌드가 다시 막히는 구간이 있었고, 사용자 노출 문구와 fallback 텍스트, aria-label까지 함께 정리해야 했다.

오늘은 기능 수정과 병행해서 다음 기준으로 복구했다.

- 사용자 노출 문구 우선 복구
- 깨진 JSX 문자열 복구
- 깨진 주석은 한글로 다시 정리
- 문서 파일도 인코딩 이슈를 같이 정리

이 작업은 단독으로는 눈에 덜 띄지만, 이후 수정 비용을 줄이는 데는 꽤 중요했다.

## 7. 브랜치를 잘못 만들었고, 마지막에는 정상 브랜치로 회수했다

오늘 작업 흐름에서 별도로 남겨둘 만한 메모는 브랜치 운영이다.

실수로 `release/0.3.0` 대신 `relaease/0.3.0` 브랜치를 파서 작업을 진행했고, 그 상태에서 커밋까지 완료됐다.

이후 정리 흐름은 다음과 같았다.

- 오타 브랜치에서 작업 완료
- 오늘 작업 커밋을 정상 브랜치 `release/0.3.0`으로 `cherry-pick`
- `release/0.3.0`과 `dev` 차이 확인
- `origin/dev`를 `release/0.3.0`에 먼저 merge
- 충돌 정리 후 다시 push



결국 지금 기준으로는

- `release/0.3.0`이 최신 작업 브랜치
- `dev`는 이후 PR로 머지 받을 브랜치
- `relaease/0.3.0`는 삭제 대상

이라는 상태로 정리됐다.

이 메모를 남기는 이유는, 오늘 코드 작업만큼이나 브랜치 정리도 실제 작업 흐름의 일부였기 때문이다.
그리고 작업시 재확인이 필요하다는 것을 느낌. 익숙한 곳에서 실수가 잦기 마련
