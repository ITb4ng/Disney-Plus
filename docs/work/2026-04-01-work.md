# 2026-04-01 Work Log

## 개요
- 배너 노출 대상을 직접 제어할 수 있도록 배너 후보 데이터를 별도 seed 구성으로 분리했다.
- 배너 선택 로직을 쿼리, seed 관리, 유효성 검사, 가중치 랜덤 선택으로 나눠서 유지보수성을 높였다.
- 상세 정보가 불완전하거나 사용할 수 없는 배너 후보를 건너뛰는 fallback 흐름을 추가했다.

## 배너 구성 정리
- 배너 후보 목록을 `bannerPickSeeds` 배열로 분리해 `id`, `type`, `key`, `title`, `enabled`, `weight`, `note`를 기준으로 관리하도록 정리했다.
- `enabled` 값으로 현재 로테이션 포함 여부를 제어할 수 있게 만들었다.
- `weight` 값으로 배너 노출 빈도를 조절할 수 있게 만들었다.
- 추후 배너 교체 시 API 호출 로직을 건드리지 않고 seed 데이터만 수정하면 되도록 구조를 분리했다.

## 선택 로직 개선
- `bannerPickRandom.js`에서 활성화된 seed만 추려서 가중치 기반 랜덤 선택을 수행하도록 분리했다.
- `bannerQueries.js`에서는 선택된 seed를 바탕으로 상세 정보를 조회하고, 실제 배너로 쓸 수 있는 필드가 있는지 한 번 더 확인하도록 정리했다.
- 사용할 수 없는 상세 데이터가 내려오면 다음 seed를 다시 선택해 재시도하도록 처리했다.
- 모든 seed가 실패하면 `null`을 반환해 상위 레이어에서 안전하게 대응할 수 있게 했다.

## 검증 레이어 추가
- `validateBannerSeed.js`를 추가해 seed 항목의 타입과 필수 필드 유효성을 검사하도록 만들었다.
- 잘못된 seed 구성이 있으면 앱 시작 시점에 콘솔 에러로 빠르게 인지할 수 있도록 했다.
- 검증 포인트는 `id`, `type`, `key`, `title`, `enabled`, `weight`, `note` 기준으로 정리했다.
