# 스크롤 복원 수동 테스트 문서

업데이트 기준: `2026-03-17`  
대상 프로젝트: `disney-plus-app`

## 1) 문서 목적
- 스크롤 복원에서 반드시 지켜야 하는 UX 기준을 명확히 정리한다.
- 라우트별로 무엇을 복원해야 하는지, 무엇은 복원하지 않아야 하는지 기준을 통일한다.
- 수동 테스트 시 어떤 흐름을 우선 확인해야 하는지 체크리스트로 관리한다.

## 2) 핵심 원칙

### 원칙 1. exact px 복원이 목적은 아니다
- 스크롤 복원은 숫자 한 칸까지 정확히 맞추는 것보다, 사용자가 보던 흐름을 잃지 않게 하는 것이 우선이다.
- 따라서 라우트 성격에 따라 `top 유지`, `이전 위치 복원`, `섹션 단위 최소 복원`을 다르게 적용한다.

### 원칙 2. 화면 성격이 다르면 정책도 달라야 한다
- `/main`: 사용자가 둘러보던 맥락이 중요하므로 뒤로가기는 이전 스크롤 복원이 우선이다.
- `/`: 랜딩 성격이 강하므로 섹션 단위 최소 복원이 맞다.
- `/detail`: 기본은 top 시작이 맞고, 일부 새로고침 상황만 예외 복원을 허용한다.
- `404`: 항상 top에서 시작해야 한다.

### 원칙 3. 잘못된 복원보다 안정적인 시작점이 낫다
- footer를 먼저 찍고 올라오거나, 잘못된 구간으로 이동하는 복원은 실패로 본다.
- 사용자가 예상 가능한 위치에서 다시 시작하게 만드는 쪽이 더 중요하다.

## 3) 반드시 지켜야 하는 사용자 흐름

### A. 메인 탐색 흐름
- `/main -> detail -> back`
  - 기대: `/main`에서 보던 세로 스크롤 위치로 복원
- `/main -> search -> back`
  - 기대: `/main` 기존 스크롤 유지
- `/main -> feedback -> back`
  - 기대: `/main` 기존 스크롤 유지
- `/main -> feedback -> 등록 -> 목록 -> back`
  - 기대: `/main` 기존 스크롤 유지

### B. 랜딩 탐색 흐름
- `/`에서 hero 구간에 있을 때 새로고침
  - 기대: top 유지
- `/`에서 top10, pricing, faq, footer 구간에 있을 때 새로고침
  - 기대: 현재 보고 있던 섹션 최상단이 nav 아래에 맞춰짐
  - 비고: exact px 복원은 목표가 아님

### C. 상세 탐색 흐름
- `/detail` 직접 진입 또는 카드 클릭 진입
  - 기대: top 시작
- `/detail`에서 trailer 또는 related row를 보다가 새로고침
  - 기대: 해당 래퍼가 절반 이상 보였던 경우에만 해당 구간 최상단을 nav 아래에 정렬
- `/detail -> back -> 이전 페이지`
  - 기대: 이전 페이지의 스크롤 위치 복원

### D. 예외 흐름
- 어떤 화면에서든 `404` 진입
  - 기대: 항상 top 시작
- `404 -> back`
  - 기대: 이전 페이지 스크롤 복원

## 4) 라우트별 정책 정리

### `/main`
- `PUSH/REPLACE` 진입: top 시작
- `POP(back/forward)`: 이전 스크롤 복원
- `reload`
  - 최상단이면 top 유지
  - 스크롤 후 새로고침이면 오버레이 후 top 기준 시작
- 실패 기준
  - footer 선노출
  - 새로고침 직후 하단으로 튀었다가 올라오는 플래시
  - detail/search/feedback에서 돌아왔는데 이전 위치를 잃는 경우

### `/`
- hero 구간: top 유지
- top10, pricing, faq, footer
  - 현재 섹션이 절반 이상 보이는 경우 섹션 최상단 기준으로 복원
  - nav 높이를 반영해 섹션이 가려지지 않아야 함
- 실패 기준
  - hero가 남아 있는데 섹션으로 점프
  - 다른 섹션으로 잘못 복원
  - 타이틀이 nav에 가려짐

### `/detail`
- 기본: top 시작
- 예외: 브라우저 새로고침에서만 trailer 또는 row 구간 조건부 복원
- poster 클릭 등 새 진입 흐름은 항상 top 시작
- 실패 기준
  - unrelated row로 이동
  - top 시작해야 할 진입에서 중간 구간으로 시작
  - reload 시 footer 또는 하단 영역 선노출

### `/404`
- 항상 top 시작
- 이전 페이지 복원 상태를 깨지 않아야 함

## 5) 수동 테스트 환경
- 브라우저 탭은 1개만 사용
- 1차 기준 해상도: `1440x900`
- 모바일 확인이 필요한 경우
  - iPhone 계열 뷰포트
  - Android Chrome 뷰포트
- 보호 라우트(`/main`, `/search`, `/detail/*`, `/feedback`)는 로그인 상태에서 확인
- 스크롤 값 확인은 가능하면 실제 스크롤 컨테이너 기준으로 본다.
  - 현재 프로젝트는 `window.scrollY`보다 `.layout.scrollTop` 체감이 중요하다.

## 6) 수동 테스트 케이스

### TC-01 `/main -> detail -> back`
1. `/main` 진입
2. `.layout` 기준 충분히 스크롤
3. 카드 클릭으로 `/detail/...` 이동
4. 브라우저 뒤로가기

기대 결과
- `/main` 기존 스크롤 위치 복원
- footer 선노출 없음

### TC-02 `/main -> search -> back`
1. `/main`에서 중간 구간까지 스크롤
2. 검색 진입
3. 닫기 또는 뒤로가기

기대 결과
- `/main` 기존 스크롤 위치 복원

### TC-03 `/main -> feedback -> back`
1. `/main` 스크롤 상태 생성
2. 피드백 진입
3. 뒤로가기

기대 결과
- `/main` 기존 스크롤 위치 복원

### TC-04 `/main -> feedback -> 등록 -> 목록 -> back`
1. `/main` 스크롤 상태 생성
2. 피드백 진입
3. 등록 화면 이동
4. 작성 후 목록 복귀
5. 뒤로가기

기대 결과
- `/main` 기존 스크롤 위치 복원

### TC-05 `/` hero 새로고침
1. `/` 진입
2. hero 구간에서 새로고침

기대 결과
- hero top 유지

### TC-06 `/` 섹션 새로고침
1. `/`에서 top10 또는 pricing 또는 faq 구간까지 스크롤
2. 현재 섹션이 절반 이상 보이게 맞춤
3. 새로고침

기대 결과
- 해당 섹션 최상단이 nav 아래에 정렬
- 다른 섹션으로 틀어지지 않음

### TC-07 `/detail` 기본 진입
1. `/main` 또는 `/search`에서 detail 진입

기대 결과
- 항상 top 시작

### TC-08 `/detail` 조건부 새로고침
1. `/detail`에서 trailer 또는 related row가 절반 이상 보이도록 스크롤
2. 새로고침

기대 결과
- 해당 래퍼 최상단이 nav 아래에 정렬

### TC-09 `404` 진입
1. 임의의 페이지에서 중간 또는 하단까지 스크롤
2. 존재하지 않는 경로로 이동

기대 결과
- 404는 항상 top 시작
- 이전 페이지 스크롤은 보존

### TC-10 `404 -> back`
1. TC-09 직후 뒤로가기

기대 결과
- 이전 페이지 스크롤 위치 복원

## 7) PASS / FAIL 기준

### PASS
- 사용자가 보던 흐름을 자연스럽게 이어갈 수 있다.
- 잘못된 섹션이나 하단 영역으로 튀지 않는다.
- nav 아래 정렬이 의도대로 보인다.
- 뒤로가기와 새로고침이 라우트 정책에 맞게 동작한다.

### FAIL
- footer가 먼저 보인다.
- 상단 플래시 또는 하단 플래시가 심하게 보인다.
- top 시작해야 하는 화면이 중간에서 시작한다.
- 이전 위치를 유지해야 하는 흐름에서 위치를 잃는다.
- 다른 섹션으로 복원된다.

## 9) 메모
- 이 문서는 exact px 검증 문서가 아니다.
- 이 문서는 "유저 흐름이 유지되는가"를 확인하는 문서다.
- 정책이 바뀌면 테스트 케이스보다 먼저 3번, 4번 기준을 갱신한다.
